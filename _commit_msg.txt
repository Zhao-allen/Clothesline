fix(setup): installer crashed on launch - drop InvariantGlobalization

v0.3.0 and v0.3.1 shipped a Clothesline-Setup.exe that did nothing when run:
no window, no error dialog, no log entry.

Cause: InstallerWPF.csproj set <InvariantGlobalization>true</...>. WPF's text
stack resolves real culture data while shaping a line, and invariant mode has
none, so the very first Measure threw:

    System.TypeInitializationException: The type initializer for
    'MS.Internal.FontCache.MajorLanguages' threw an exception.
     ---> System.Globalization.CultureNotFoundException:
          Only the invariant culture is supported in globalization-invariant
          mode. (Parameter 'name')  en is an invalid culture identifier.

It surfaced in Window.Show() -> TextBox.MeasureOverride, i.e. while laying out
the language picker, so the process died before any window existed. A WPF app
with no console and no handler writes nothing anywhere, which is why it looked
inert rather than broken. Ironically the crash landed on the one screen that
exists to render five languages.

Fix: remove the property and leave globalization on (the default). It costs a
few MB of ICU data in the self-contained bundle; a working installer is worth
more than that. The comment on the property now records why it must not come
back.

Verified by building the single-file publish and running it: it crashed before
the change, and the window comes up after.

to .gitignore.
